# Chrome Web Store Privacy Practices

## Single purpose

把灵感预设（Ampira）、用户选择的 Chrome 书签与资讯来源整理成可搜索的新标签页信息看板。

## Permission justifications

Network header images use ordinary credential-free, no-referrer image requests and a device-local CacheStorage copy. Only one response is retained, with its storage usage included in the existing 25 MiB / 30-day cache budget. Cache hits make no remote request, including for hosts without CORS support. Clearing caches or factory reset deletes the response. Image bytes are neither synced nor exported; no additional permission is required.

User-selected video covers support HTTPS video files and download URLs, including redirects (loopback HTTP is allowed for development). The extension streams them in the browser without site credentials or referrer information and without requiring the host to grant cross-origin read access. They play muted and pause in background tabs or under reduced motion. Network video bytes are not retained in Ampira’s image cache; only the URL and media type follow ordinary appearance settings, sync, and exports. Local MP4/WebM files up to 100 MB are saved unchanged, including original metadata, in this device’s extension IndexedDB; they are never uploaded, synced, or exported. Replacing, removing, factory resetting, or uninstalling deletes the corresponding local copy. Failed playback restores the default cover. No additional permission is required.

Chrome Web Store marks every permission-justification field generated from `permissions`, `optional_permissions`, and `optional_host_permissions` as required. “Optional” below means the user grants the capability at runtime; it does not make the dashboard disclosure optional.

- `activeTab`: After the user clicks the Ampira toolbar icon, temporarily read only that tab's title and URL so the page can be added to the reading queue. Access ends when the tab navigates or closes; it does not provide passive tab monitoring, full browsing history, page content, or background access to other tabs.
- `bookmarks`: Read user-selected folders for dashboard sections and all bookmark titles, URLs and folder paths for local search after bookmark consent. For directed research, Ampira reads metadata only from the one folder explicitly selected for that turn. Ampira never calls bookmark create, update, move, or remove methods. Chrome displays “Read and change your bookmarks” because the API has no read-only permission.
- `storage`: Store synchronized preferences, local content state, and user-entered API credentials that stay local by default and enter browser account sync only after a separate explicit opt-in.
- `alarms`: Wake the Manifest V3 service worker every 15 minutes to check whether authorized sources are due for refresh.
- Optional `favicon`: Requested only after an explicit user action to use Chrome's built-in Favicon API for URLs already displayed in Ampira. It does not grant tab or browsing-history access, and no URLs are sent to a third-party icon service. Users can revoke it in Settings → Browser.
- Optional `search`: Requested from Settings → Browser or an explicit search-list action. Chrome Search submits the query to the default provider in the requesting tab. Revoking permission disables this action; local search remains available. Queries are not stored, synchronized or sent to the developer.
- Optional `history`: Default off. After an explicit enable action, query browser-retained history for matching titles, URLs and last-visit times, with at most 200 candidates per query. Results are transient and local, with no persistent copy, sync or AI/Bot transfer. No background visit collection or history write APIs. Revocation and history deletion invalidate results. Factory reset revokes permission without deleting browser history.
- Optional website origins: Fetch public feeds and article text, read public cover-image metadata, or refresh a website explicitly included in a directed-research turn; connect to the user-configured AI provider or optional Brave image-search API. Access is requested from a user gesture and limited to exact origins. The first public-source authorization requests the exact domains needed by the current interface-language pack together, deduplicating shared domains: 14 native-language sources that work without AI setup and three reserved cross-language major-news sources. The reserved sources remain unused until the built-in AI is fully configured or Bot news organization is enabled. The packaged preset adds no origin permission. Reader first attempts a credential-free, no-referrer request under the destination site’s ordinary CORS policy; if that public read succeeds, no website origin is requested and the result is not written to the permission-bound Reader cache. If the read is blocked, one credential-free, content-free HEAD request distinguishes an unreachable site from a reachable site that needs access. Only the latter offers the exact site origin from a subsequent explicit user action. AI-analysis and research origins are likewise requested at runtime after a user gesture. A Feed discovered on a different domain is recorded as pending and is not contacted unless the user separately grants that exact origin.
- Optional Open-Meteo origins: When the user submits a city in Weather mode, request only `https://geocoding-api.open-meteo.com/*` and `https://api.open-meteo.com/*`. A bundled GeoNames-derived index resolves matching Chinese county-level-or-above administrative places locally; otherwise the first Open-Meteo origin resolves user-entered city text to explicit candidates. The forecast origin receives coordinates only after the user selects one candidate and returns current conditions, including humidity and wind speed, plus the next five days of forecasts. Compact cards display the next two days; large cards display all five. Ampira does not request geolocation, does not refresh weather in the background, and lets the user revoke either origin in Settings → Browser.

## Data disclosures

- Default header image: uses an Unsplash image at images.unsplash.com through the ordinary network-header loading and cache workflow. The image host receives ordinary network information such as the IP address. Users can replace or disable the header in Appearance settings.

- Native-first Bot mode: the extension handles routine sources and actions. Only authorized bounded evidence for briefs, explicit questions and optionally enabled news organization is sent to the local companion. Article URLs are read within existing permissions. Question context is conversation-specific, module tools return bounded pages, and the service generates reply metadata. No whole bookmark tree, browsing history or unrelated AI chat history is exported. Automatic brief evidence is rechecked before display; previously delivered external AI context cannot be retracted.

- Optional Bot news organization: default off. While MCP and Bot mode are active, automatic, batch and individual summaries (including translation) send authorized cached titles and excerpts of at most 2,000 characters in batches of up to five to the authenticated local companion. No AI keys, bookmark tree or browsing history are included. Verified results are reused by source fingerprint and target language; waiting or failure does not fall back to the built-in API. Source permission, settings generation, pairing and locale are rechecked before applying results. An explicitly configured runner uses its signed-in account allowance.
- News evidence: short display excerpts are separate from bounded feed text and supplemented article text, each capped at 12,000 characters per item. Refresh may read up to eight already authorized same-origin article bodies, at most two per source, when feed material is short; requests omit login credentials. Enabled built-in AI card organization uses at most 6,000 characters per item; Bot retains its existing 2,000-character request limit. Content and modification dates govern summary/brief invalidation. Supplemental material follows the existing local cache quota, retention and deletion controls.

- MCP quick setup: the master switch controls this browser’s integration while preserving independent mode choices. Copy setup instructions explicitly shares a ten-minute pairing code and the extension ID with the user’s local-command AI. The companion and extension exchange the long-term key directly. The local launcher prints only MCP client configuration. The background companion can be reused by several local clients and is stopped separately.
- Optional Bot board mode: Settings → MCP lets users independently choose assistant handling for daily briefs, news summaries and AI chat. Unchecked features use the existing AI settings; the choices save immediately and persist when MCP is turned off. Enabling MCP or copying setup requests optional `http://127.0.0.1/*` access from that user gesture; automatic pairing verifies the loopback service. The page shows only a read-only address and a disconnect action, with no manual key form. The browser pairing key stays local, outside sync and exports. The companion binds only to 127.0.0.1 and checks Host, Origin and authentication. Browser caches are isolated by address and board identity. The companion stores board content, messages and receipts in a separate local data directory, without additional encryption; resetting or uninstalling the extension does not delete it. Authorized AI clients may send MCP content to their model provider according to their own settings. To-do actions stay in the extension. The companion does not start a model by default. Explicitly enabling its local Codex runner sends bounded brief, question and news-summary evidence to the signed-in Codex account for automatic generation, using that account’s allowance. Temporary output files are cleaned after each run; failures pause until an explicit retry. The developer receives none of this content. HTTPS images may still contact their image hosts.
- Website content: selected public Feed and article content, plus public cover metadata and image URLs from authorized pages. Directed research may refresh up to four relevant authorized sites and read the three highest-ranked articles. Bookmark titles and URLs remain non-citable candidates. The research cache stores only a small set of passages read from Feed or Reader plus their titles, URLs, source identity, publication dates, and fetch times—not separately extracted full text—and is limited to 30 days, 2,000 entries, or about 6 MiB. After a user opens Reader, article text may also be read without host permission when the destination site explicitly permits the ordinary CORS request; the request omits credentials and referrer information, and that result is not added to the permission-bound Reader cache. Inspiration preset (Ampira) contains 48 public HTTPS links and 24 original WebP covers packaged with the extension; it creates or changes no bookmarks and makes no remote cover request. When an authorized Feed item has no usable image, Ampira may read up to 1 MiB of inert image metadata from the same-origin article page; it does not request another origin or execute page scripts. Public sources (Ampira) are enabled by default, can be disabled in Settings, and add public news alongside bookmark sources only after the user grants each exact source origin. Native public items must match the interface language. Cross-language items remain hidden unless their Feed title and summary are successfully localized and validated in the interface language. Feed discovery results, response validators, image-coverage counts, and recent per-source success or failure diagnostics remain in the extension-local cache and are cleared with generated cache data.
- Web browsing activity: bookmark titles/URLs from sources selected by the user, the title and URL of a page explicitly added through the toolbar, article URLs placed in the reading queue or used as AI or research context, explicit reading state, and optionally enabled query-matched browser history for transient local suggestions. Reading-queue records remain local by default. If the user enables Sync reading queue, Chrome Sync copies at most the 40 most recent queue records—including title, URL, source, and added time—to the user's other signed-in synced Chrome installations. They are never sent to the developer. Depending on the feature path and extension version, an AI-context URL can be the stored source URL or a normalized/minimized form, and can still contain path or query information.
- Authentication information: user-entered API credentials stay in extension-local storage by default. The separate, default-off Sync API keys and AI configuration switch copies AI and Brave image-search keys together with the AI service URL, API protocol, and model into browser account sync. Ampira adds no encryption or sync password. Browser sign-in and extension sync are required. New devices still require their own AI data consent and website permissions. Disabling removes the synced copy and keeps each device's last received local configuration; clearing a key while sync is enabled propagates that deletion. The complete record follows the browser's last-write-wins sync behavior. Keys never appear in public settings responses or exports and are not sent to the developer. Provider requests send the corresponding key directly to that provider for authentication.
- AI transfers: after prominent disclosure and complete AI configuration, questions, up to twelve conversation turns, article context, and the selected current-turn research evidence (titles, excerpts, and URLs) are sent to the user's configured provider. Cross-language Feed titles, summaries, and article URLs from the initially authorized public-source pack are also sent automatically so they can be localized before display. Failed or wrong-language output, disabled AI, and exhausted quota keep the raw foreign-language item hidden from the Feed, daily brief, local search, and AI search context.
- User-generated content: explicit AI or research questions, optional browser-search queries, source preferences, and an optional user-selected local cover image or video. Browser-search queries go directly through Chrome to the user's default search provider and are not stored or sent to the developer. When the user enables conversational web search, the query goes to the configured AI provider with its native hosted-search tool enabled; answers and cited sources remain in that page session and are not written to IndexedDB. The cover image is re-encoded as WebP in the browser to remove original-file metadata, stays only in the current Chrome profile's local extension storage, is never synchronized or exported, and is never sent to the developer or another provider.
- Location: matching Chinese administrative-place queries are resolved inside the extension from a bundled GeoNames-derived index and are not transmitted for search. Other manually entered city queries are sent directly to Open-Meteo's Geocoding API. The latitude and longitude of the user's explicitly selected result are sent directly to Open-Meteo's Forecast API. The selected display name, administrative hierarchy, provider marker, and coordinates remain local by default. If the user enables Sync weather city, Chrome Sync copies that selected-location record to the user's other signed-in synced Chrome installations. Forecast responses are never synchronized, and the developer cannot access synchronized content. Ampira never reads browser or device geolocation.
- To-dos: text, completion state, and timestamps remain in extension-local client state by default. If the user enables Sync to-dos, Chrome Sync copies those records to the user's other signed-in synced Chrome installations. They are not sent to a provider or the developer and are not removed by ordinary cache clearing or interface-preference reset.
- Synchronized settings and optional content: some non-credential settings use Chrome Sync. Reading queue, to-dos, weather city, stock watchlist, countdowns, topic-tracking rules, calendar events, quick notes, and world clock cities are separately opt-in and default off. Watchlist sync stores up to 12 symbols; countdown sync stores up to 20 event IDs, names, and target dates. Calendar sync includes up to 200 event IDs, names, dates and optional start times; display choices and unsaved drafts stay local. Calendar sync does not partially upload events to satisfy a quota: if the shared storage budget or merged event limit is exceeded, local data remains saved and the user can retry after reducing synced content. Disabling a content-sync switch removes that category's Chrome Sync copy while preserving the local copy. Factory reset under Settings → About clears extension-local data and optional permissions on the current device and deletes Ampira settings, the optional credential-sync record, and opted-in content from Chrome Sync. Other devices retain their last received local credential configuration after that sync record is removed. Those synced deletions propagate to other signed-in synced installations but do not remotely erase local-only data unique to those devices. Per-record versions and temporary deletion markers merge changes between devices; old deletion markers are removed after 30 days.
- Remote images: preset inspiration cards use only packaged local covers and never enter the remote preview or Brave pipelines. News cards prefer safe Feed and authorized original-page candidates; personal-bookmark inspiration cards prefer up to three images declared by an authorized original page and start preloading all three reshuffle batches immediately before first render. Web image search is optional. It uses Brave only when a news or personal inspiration card has no usable original image or every original fails to load; Reader images do not use it. Displaying or preloading a remote image makes a direct request to the image host. Ampira does not proxy that request; the host receives ordinary network information needed to serve the image.
- Research scopes: bookmark-folder research and provider-native web search are independent, default-off, session-only controls. The default search path reads neither an unselected private folder nor a hosted web-search tool. Folder-only mode never calls a search engine; web-only mode never reads private bookmark folders; enabling both runs the two user-selected paths together. The optional Brave credential belongs only to fallback image search.

## Certifications

- Data is used only for the extension’s user-facing single purpose.
- Data is not sold, used for creditworthiness, advertising, or unrelated personalization.
- Data is not transferred to the developer.
- AI content transfers occur only after prominent in-product disclosure and consent. Provider-native web search runs only after the user enables the per-turn control. Brave image queries occur only after the user separately enables and configures fallback image search.
- Open-Meteo city and coordinate transfers occur only after the user opens Weather mode and submits a non-local match or selects a city. Weather data is visibly attributed to Open-Meteo; bundled China location candidates are visibly attributed to GeoNames under CC BY 4.0. The applicable service terms and data licences are checked before release.
- The developer cannot access handled user data because there is no developer-operated backend.
- The use of information received from Google APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements.

- Markets is opt-in: adding a stock or authorizing a synced watchlist requests only `https://qt.gtimg.cn/*`. Watchlist symbols are sent directly to Tencent Finance for A-share, Hong Kong and US quotes. The watchlist stays in local IndexedDB by default and can be separately opted into browser account sync. New devices still require user authorization for the quote provider. Quote caches always remain local. Watchlists and quotes never enter AI/Bot requests. Refresh checks run every minute only while the page is visible and a Markets card is displayed, with manual refresh available. Market-local quote times and delayed/stale labels are visible. Revocation stops requests and deletes quote caches while retaining the watchlist. The provider endpoint was checked with public symbols during development; market-data redistribution rights still require review before store publication.

- Quick notes and world clock: notes store up to 50 records of 2,000 characters, with text, pin status and timestamps. World clock stores up to 8 cities and uses browser time zone data without geolocation or external time requests. Both are local by default with separate opt-in sync switches. Unsaved drafts and local revisions stay local. Sync failures preserve local content and expose retry; neither dataset silently drops records to fit a quota. No content is sent to AI, Bot or the developer. Note-to-task conversion preserves the note and follows the independent to-do sync option.
