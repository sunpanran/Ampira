Data and privacy

Ampira Privacy Policy

Effective: November 6, 2026

Ampira’s single purpose is to turn Inspiration preset (Ampira), user-selected browser bookmarks, and news sources into a searchable New Tab information dashboard. Ampira has no developer-operated server, account system, advertising, or analytics.

Optional AI assistant dashboard

The AI assistant dashboard lets users select daily briefs, news summaries and AI chat independently. Unchecked features use the existing AI settings. Ampira handles weather, to-dos, feed collection, ranking, events and inspiration; new assistant tasks are submitted only for selected features. Ampira may send bounded authorized news candidates or references matching an explicit question to the local companion; explicitly requested article URLs can be extracted within existing site permissions. It does not automatically upload the whole bookmark tree, browsing history or other AI applications’ chat history. Briefs are reused by date and evidence; questions include only bounded history from the same conversation. The companion stores bounded tasks, submitted questions and their references. It does not start a model by default. If the user explicitly enables the local Codex runner, queued briefs, questions and opted-in news summaries are generated and returned through the signed-in Codex account, using that account’s allowance. Task evidence is sent to Codex; temporary result files are removed after each run. Failed or interrupted runs require an explicit retry. The extension does not read Codex credentials or other chat history.

“News summaries” under “Assistant handles” defaults off and requires MCP and AI assistant dashboard mode. Automatic, batch and individual organization, including translation, sends authorized cached titles and excerpts of at most 2,000 characters in batches of up to five to the local companion for the authorized AI assistant. No API keys, bookmark tree or browsing history are sent. Validated summaries are cached by source fingerprint and language. Waiting or failure does not switch to the built-in AI. The companion stores bounded tasks; an explicitly configured local runner processes them using its account allowance.

The MCP master switch, assistant dashboard mode and feature selections are saved separately, and changes take effect immediately. Enabling MCP or clicking “Copy setup instructions” requests optional http://127.0.0.1/* access from that user gesture. The instructions contain a one-time pairing code valid for ten minutes and the extension ID, which the user explicitly gives to an AI with local command access. The long-term key passes directly between the companion and extension, outside copied instructions, command output and public settings. The page has no manual key form.

Turning MCP off preserves pairing and mode choices. Connection details show a read-only service address and allow browser pairing to be removed even while MCP is off. These actions do not delete delivered content, stop the independent companion or stop external assistant tasks. Changed source permissions prevent unauthorized content from displaying, but cannot retract material already delivered to an external AI conversation.

The pairing key stays in this browser’s chrome.storage.local and the companion’s local data directory, outside sync and exports. Browser caches are isolated by address and board identity. The companion binds only to 127.0.0.1, checks Host, Origin and authentication, and stores board content, messages and deduplication records in .ampira-mcp under the user’s home directory by default, without additional encryption. Authorized AI clients may send MCP content to their model provider according to client settings; the developer receives none. Disconnecting, resetting or uninstalling the extension does not delete the companion’s data directory. Stop the service before managing that directory separately.

Data handled

  • Bookmark titles, URLs and folder paths, after bookmark consent. Local search includes all bookmarks; dashboard sources still use selected folders.
  • Public Feeds, page titles, summaries, article text, and inspiration-page cover metadata and image URLs from user-authorized sources.
  • Interface settings, reading queue, archive, source preferences, caches, and search questions; page titles and URLs explicitly added to Read later through the toolbar or an Ampira card are stored in the reading queue.
  • User-entered to-dos and the city, administrative area, country, and coordinates of a manually selected weather location.
  • Optional AI credentials or a Brave Image Search API key entered by the user.

Purpose and storage

The default header uses a remote image from Unsplash (images.unsplash.com) and follows the network header loading and caching rules below. Displaying it sends ordinary network information, such as the IP address, to the image host. Users can replace or disable the header in Appearance settings.

Ampira uses chrome.storage.sync for some non-credential settings. Reading queue, to-dos, selected weather city, stock watchlist, and countdowns stay in extension IndexedDB by default; users can separately opt each category into sync under Settings → Browser → Cross-device sync. News, summaries, search caches, full reading state, utility-card mode, and forecast caches always remain local. A user-selected local cover is re-encoded as WebP in the browser to remove original-file metadata and is stored only in chrome.storage.local for the current browser profile; it is not included in browser account sync or settings exports, and replacing, removing, or uninstalling clears the corresponding local copy. API keys and AI service configuration stay in the current browser profile's chrome.storage.local by default, and full keys are not shown again after saving.

Sync API keys and AI configuration is off by default and must be enabled separately. The Sync personal content switch does not turn it on. When enabled, AI and Brave image-search keys are saved together with the AI service URL, API protocol and model in your browser account's sync storage (chrome.storage.sync). Ampira adds no encryption or sync password. Each device must use the same browser account with extension sync enabled. On new devices, you still need to agree to AI data sharing and allow access to service websites.

Turning key sync off or performing a factory reset removes the copy in your browser account. Settings already received on other devices stay there. If you remove an individual key while sync is on, that key is also removed from other devices through sync. If several devices edit the settings at once, the complete set of keys and AI settings last written by the browser takes precedence. Keys are not included in configuration exports or sent to the developer.

Reading-queue sync stores at most the 40 most recent titles, URLs, sources, and added times. To-do sync stores text, completion state, and timestamps. Weather-city sync stores the display name, administrative hierarchy, provider marker, and coordinates, but never forecast responses. Stock-watchlist sync stores up to 12 symbols. Countdown sync stores up to 20 event IDs, names, and target dates. All five switches default off. Turning one off removes that category’s browser account sync copy while preserving local content. Ampira merges device changes with per-record versions and deletion markers retained for at most 30 days. The developer cannot access this browser account sync content. Clearing generated caches or resetting interface preferences does not remove to-dos; uninstalling removes local copies, while synced copies follow browser account sync state and these user controls.

Public sources (Ampira) are enabled by default to add public news alongside bookmark sources, and users can turn them off in Settings. The first public-source authorization lists the exact domains needed by the current interface-language pack together, deduplicating shared domains: 14 native-language sources that work without AI setup and three reserved cross-language major-news sources. Reserved sources are read only after the built-in AI is fully configured or Bot news organization is enabled, and still require their exact website permissions. A cross-language item is shown only after its title and summary are successfully localized and validated in the current interface language; raw foreign-language content stays hidden without a valid localized result. Valid Bot summaries do not require a built-in AI key. If an allowed page declares a Feed on another domain, Ampira records and displays that pending domain but does not connect until the user separately allows it.

The inspiration source is a one-at-a-time choice between Inspiration preset (Ampira) and the user’s existing bookmark folder. Switching never creates, changes, or removes browser bookmarks and preserves the selected personal folder. The preset contains 48 public HTTPS links and 24 original covers packaged with the extension. Preset covers make no remote image requests, and preset links do not automatically enter website-origin permissions. When the user opens in-app reading, Ampira first tries the access publicly allowed by the site’s CORS policy; only if the site blocks that read does Ampira offer exact-domain access and retry. AI analysis still requests a required exact origin only after an explicit user action.

For remote images, Ampira reads inert public page metadata only after the user allows the exact site domain. If an authorized Feed item has no usable image, Ampira may make a limited read of image metadata from the first 1 MiB of the strictly same-origin article page; it does not contact another article origin or execute page scripts. News cards try Feed and original-page image candidates. In personal-bookmark mode, inspiration cards try up to three original-page candidates and start preloading all three reshuffle batches before first render. Web image search uses Brave only when a news or personal inspiration card has no usable original image or every original fails to load, and only after the user has enabled and configured it. It is not used for preset covers or Reader images.

Both research-search scopes default off and are not persisted. For a turn, the user may select one bookmark folder for directed research, enable provider-native web search when the configured AI supports it, or enable both. Ampira reads bookmark metadata only from the selected folder for directed research; bookmark titles and URLs form a candidate index and cannot directly become answer evidence. Live Feed or article reads still require exact-origin access granted by the user. The research cache stores only a small set of passages read from Feed or Reader plus their titles, URLs, source identity, publication dates, and fetch times, never separately extracted full text, and is pruned at the first of 30 days, 2,000 entries, or about 6 MiB. Web answers and sources stay in the current page session and are not written to IndexedDB. Turning web search off means Ampira does not enable the AI provider's web-search tool.

Network header images are cached on this device after the first load and reused on later visits. Image requests omit credentials and referrer information and follow the browser's normal image-loading rules. At most one network cover response is retained in CacheStorage; its usage counts toward the existing approximately 25 MB, 30-day cache budget. The image is not synced or included in settings exports. Loading a different network image replaces the cached copy; clearing caches, factory reset, or uninstalling removes it.

Header backgrounds also support user-provided HTTPS video links. The browser loads the selected video directly and loops it silently, pausing when the page is hidden or reduced motion is enabled. Playback failures restore the default background. Requests omit site credentials and referrer information; the host must allow cross-origin playback and still receives ordinary network information such as the IP address. Video bytes are not added to Ampira’s image cache, account sync, or exports. The URL and media type are saved, synced, and exported as appearance settings.

Third-party transfers

Without user action, Ampira does not send bookmarks, reading state, or search questions to the developer or a third party. When the user opens in-app reading, Ampira first connects directly to the public website with an ordinary CORS request that omits credentials and referrer information. If the browser blocks that read, Ampira may make one credential-free HEAD request that reads no content to distinguish an unreachable site from one that needs access. A successful public read does not request website access or enter the permission-bound Reader cache. When a dashboard card or the reader displays a remote image, the browser requests it directly from the image host. Even when no referring-page information is sent, that host receives ordinary network information required for the request, such as the IP address and browser information. Ampira does not proxy these requests.

When the user explicitly enables AI, submitted questions, up to twelve conversation turns, article titles, summaries, selected text, article URLs needed for context, and the selected research evidence for that turn (titles, excerpts, and URLs) are sent to the provider configured by that user. If the initial public-source authorization already includes cross-language sources, their Feed titles, summaries, and article URLs are sent automatically to that provider once AI is fully configured; this is required before those items can enter the Feed, daily brief, or search. Depending on the feature path and extension version, the article URL may be the URL stored by the source or a normalized or minimized form with unnecessary information removed. A URL may still contain path or query information and should be treated as transmitted data. The AI API key is sent directly with the request to the configured provider solely to authenticate that request; it is not sent to the Ampira developer.

When the user explicitly enables conversational web search, the query goes to the configured AI provider with that provider's native hosted-search tool enabled; availability depends on the provider, API, and model. The optional Brave Image Search API key is used only for separately enabled replacement-image search. Conversational web search does not fall back to the browser's default search provider. These third-party transfers use HTTPS. HTTP is allowed only for a user-configured localhost service.

The navigation search button open one suggestions list for Ampira content and all browser bookmarks. Browsing-history search is off by default. After the user enables optional history permission in Settings → Browser or the suggestions list, Ampira queries browser-retained history by the entered keywords, with up to 200 candidates per query. Matching results stay in the page session: no background visit collection, history modification, persistent copy, synchronization, or transfer to the developer, AI providers or local Bot. Revoking permission or deleting history invalidates results. Factory reset revokes this permission without deleting browser history. Explicitly choosing web search sends the query through the browser API to the default provider in the requesting Ampira tab; Ampira does not store the query. URL navigation and ordinary bookmark/history results open a new tab.

Only after the user submits a city in the weather card does Ampira request access to Open-Meteo’s Geocoding API and Weather Forecast API origins. Queries matching Chinese county-level-or-above administrative places are resolved locally from a bundled GeoNames-derived index and are not transmitted for search; other city queries are sent directly to Open-Meteo’s Geocoding API. After the user explicitly selects a matching city, its latitude and longitude are sent directly to the forecast API. Ampira does not use browser geolocation, and the developer cannot access these queries, coordinates, or weather results. Chinese location candidates attribute GeoNames under CC BY 4.0, and weather data is attributed under Open-Meteo’s terms and license.

Only after a user clicks Add or Authorize in the Markets card does Ampira request the exact https://qt.gtimg.cn/* origin and send watchlist symbols directly to Tencent Finance. A-shares, Hong Kong and US stocks are supported. Quotes are checked every minute while the page is visible and a Markets card is displayed, or on manual refresh. The watchlist stays in local IndexedDB by default and can be separately opted into browser account sync. New devices still require user authorization for the quote provider. Quote caches always remain local. Neither watchlists nor quotes are sent to AI, the Bot or the developer. Quotes show market local time and may be delayed; cached results are labelled when a refresh fails. Revoking this origin under Settings → Browser stops requests and removes cached quotes while keeping the watchlist.

Countdown event names and target dates stay in local IndexedDB by default and can be separately opted into browser account sync. They are not sent to AI, the Bot, the developer or other content services. Day counts use the browser’s local calendar date. Deleting an event or performing a factory reset removes the corresponding records.

Permissions

activeTab temporarily reads only the current tab’s title and URL after the user clicks the Ampira toolbar icon, so the page can be added to Read later. Access ends when the tab navigates or closes and does not provide continuous tab or browsing-history access. The reading queue enters browser account sync only if the user separately enables its default-off switch. bookmarks provides read-only bookmark organization and user-selected folder research; Ampira does not call bookmark write APIs. storage stores local settings and caches plus content the user chooses to place in browser account sync. alarms checks due sources every 15 minutes. The optional search permission is requested only after the user enables browser search and uses the browser's built-in API with the user's default search provider; it can be removed from the same setting and is not synchronized or exported. The optional favicon permission is requested only after a user action and uses the browser’s built-in API to display icons for bookmark and page URLs already shown by Ampira; it does not grant browsing-history or continuous tab access, and those URLs are not sent to a third-party icon service. When Microsoft Edge does not expose this service, Ampira does not request the permission and uses its packaged icon instead. Website-origin access and https://api.search.brave.com/* are likewise optional and requested for exact origins only after a user gesture. Weather requests only the exact https://geocoding-api.open-meteo.com/* and https://api.open-meteo.com/* origins when the user submits a city. Each can be revoked in Settings → Browser; revocation stops requests and removes the weather cache while preserving the selected city.

Sharing, sale, and retention

Ampira does not sell, share, or use data for advertising. News cache is retained for at most 30 days and limited to about 25 MB; directed-research cache is limited to 30 days, 2,000 entries, or about 6 MiB. Weather data is reused for 30 minutes and, if refresh fails, may fall back only to data no more than 6 hours old. Users can clear caches at any time or use Factory reset under Settings → About → Import & export to clear local Ampira data, optional permissions, and Ampira settings plus opted-in content in browser account sync. Synced deletions propagate to other devices on the same account but do not remotely erase local-only data unique to those devices. Uninstalling removes extension-local data; browser account sync data continues to follow the browser’s synchronization rules.

Chrome Web Store Limited Use

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements. Ampira uses that data only for its disclosed single purpose and user-facing features; it does not use it for personalized advertising, credit assessment, or data resale. Ampira has no backend through which its developer or personnel can read that data.

Contact

Use the project support channel for privacy or support questions. Never include API keys, private bookmarks, or personal browsing information.
