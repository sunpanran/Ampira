Data management

Data deletion

  1. Under Settings → About, select Factory reset to clear this device's Ampira settings, API keys, consent, local cover, caches and user content, and remove optional permissions. It also deletes Ampira settings and any synced copies of Read later, to-dos, weather city, stock watchlist, countdowns, topic-tracking rules, calendar events, quick notes, world clock cities, keys and AI configuration from your browser account. Synced deletions affect other devices on the same account, but do not remotely erase data stored only on those devices. Browser bookmarks are not changed.
  2. On the News page in Settings, select Clear cache to remove news, summaries, search caches, and source-quality records.
  3. Under Settings → Bookmarks → Custom feeds, remove an entry and save settings to delete its local subscription configuration. Website permissions can be revoked separately on the Browser page.
  4. On the AI page in Settings, select Remove key or Remove image key to delete that key from this device. If key sync is on, the key is also deleted from other devices through sync.
  5. Uninstall Ampira from chrome://extensions in Chrome or edge://extensions in Microsoft Edge to remove its IndexedDB, API keys, and local extension storage.
  6. To stop syncing just one category, turn off its switch under Settings → Browser → Cross-device sync. This removes that category's copy from your browser account. Content or AI settings already received on each device stay there.
  7. For Bot board, use Disconnect under Settings → MCP → Connection details, including while MCP is off, to delete the browser’s address and pairing key. Switch to Standard mode and use Factory reset to clear its cached content and delivery records. Stop the companion service before separately deleting its data directory (by default .ampira-mcp under your home directory), which holds board content, messages and deduplication records. Remove or stop MCP configuration and tasks in your AI client separately.

Ampira has no developer-operated account or server, so there is no cloud user database for the developer to delete.
