# Ampira 本地 MCP 服务

无需租用服务器。Node.js 20 或更新版本即可运行，无第三方依赖。辅助服务与扩展分开运行，不进入扩展 ZIP。

## 快速接入

1. 打开 Ampira「设置 → MCP」并开启总开关，同意浏览器访问本机地址。
2. 点击「复制接入指令」，粘贴给能执行本机命令的 AI。电脑上需要本项目和 Node.js 20 或更新版本。
3. AI 在本机找到项目，执行指令中的 connect.mjs。它启动仅监听 127.0.0.1 的后台服务，并返回 stdio MCP 客户端配置。
4. 保持 MCP 设置页打开，Ampira 自动完成配对。一次性配对码在 10 分钟后失效；长期密钥由本机程序与扩展交换，不进入复制指令或命令输出。
5. AI 按输出将 ampira 加入客户端；不能热加载的客户端需要重载 MCP，只有 tools/list 成功才表示 AI 工具可用。
6. 单独开启 **AI 助手看板**，在“接管内容”中分别选择今日简报、资讯整理和 AI 问答；未勾选项沿用原有 AI 设置。

接入命令只使用本项目文件，不下载或执行远程脚本。没有本机文件或执行能力的纯聊天客户端不能完成此流程。

## 客户端与本机服务

浏览器页面只提供自动接入，不再要求手动填写地址或密钥。默认服务数据位于用户主目录的 .ampira-mcp；长期密钥保存在其中的 connection.json，由程序处理，不应传给 AI。已配对的服务地址可在「连接信息」只读查看，并可单独移除浏览器配对。

推荐 stdio 入口为 integrations/local-mcp/client.mjs。客户端配置使用 Node 可执行文件作为 command，并以该文件的绝对路径作为第一个 args；可添加 --data-dir 和 --port。client.mjs 会复用已有后台服务，服务未运行时自动启动，因此多个本机 AI 客户端可以使用同一数据目录。server.mjs 仅作为后台服务入口，由启动器管理；不要将它配置为 stdio 客户端。

快速接入使用指令中指定的端口。AI 客户端配置中的 --port 需要与浏览器配对地址一致。

后台服务在 AI 客户端退出后仍可运行。关闭 MCP 总开关会停止当前浏览器的 MCP 读写，不会结束独立辅助服务或撤回已发送给 AI 的内容。需要停止服务时运行：

```powershell
node integrations/local-mcp/connect.mjs --stop
```

自定义数据目录时附加 --data-dir。电脑关闭后服务停止；下次 AI 客户端调用 client.mjs 时可自动启动。

## 使用

在 Ampira 开启 Bot 看板；接入指令已包含基本使用说明。让 AI 助手处理 Ampira 的待处理简报和问题；资讯整理（含外文翻译）由开关选择。天气、待办、资讯、事件和灵感由插件处理，不需要助手重写。

`ampira_publish` 仅发布已有简报（today）或回复（replies），接受 `id`、`module`、可选 `bot` 以及 `set` / `upsert` / `remove`。返回成功表示数据已经保存。重试同一更新时复用原编号和参数；修改内容时换一个编号。详细字段见[数据协议](PROTOCOL.md)。

仅配对 MCP 时，服务不会自动唤醒模型。需要点击后自动生成，可启用下面的本机 Codex 执行器。仅支持云端远程 MCP 地址的客户端无法直接使用此 stdio 服务。浏览器在有自动任务等待或生成时约每 2 秒读取可见看板的更新，空闲或失败时每 10 秒读取；这只查询本机状态，不调用模型。简报随看板刷新同步任务和有效期，完成后复用当天结果；辅助服务停止、电脑关机或休眠后只显示已有缓存。

## 自动生成简报与对话

在本机已安装并登录 Codex CLI、用户选择自动处理后，执行：

```powershell
node integrations/local-mcp/connect.mjs --runner codex
```

若提示服务需要更新，先执行 `connect.mjs --stop`，再运行上面的命令。找不到命令时，可用 `--codex-path` 指定 Codex 可执行文件的绝对路径（Windows 为 `.exe`）。自定义数据目录或端口时沿用原来的 `--data-dir`、`--port`。配置保存在辅助服务数据目录；重启服务后继续有效，现有配对和内容会保留。扩展更新后需在扩展管理页重新加载并打开新标签页，才能看到新的执行状态和重试按钮。

执行器使用 `codex exec` 和当前 Codex 登录账户的用量，显式使用 `low` 推理强度以减少等待；每次只处理一项简报、一批同会话问题或最多五条资讯整理，结果经过原有校验后写回看板。已授权的每日简报任务和用户消息进入队列即触发执行；空队列不调用模型。资讯整理任务也进入串行队列，问答和简报优先；同类整理优先手动条目。本机执行器不接管当前 Codex 聊天，也不读取其聊天历史。

运行使用临时工作目录、只读沙箱与结构化输出，忽略用户项目配置，不启用 Shell、外部应用、其他 MCP 插件或联网搜索；只接收任务中已有的资料。结果文件在运行结束后清理。运行状态不暴露命令路径、诊断文本或凭据。失败会暂停队列，页面显示原因，点击“重试生成”才会再次调用；重启时发现未完成的运行也按中断处理，不自动重复计费。每次生成最多等待三分钟。

Windows 商店版 Codex 更新后，旧版本目录可能被移除。执行器在启动前会检查原路径；仅当失效路径属于商店版 Codex 时，通过 Windows 当前用户的已注册安装信息寻找同一包家族的新路径。仍有效的路径和自定义执行器保持原选择，不从其他程序或临时目录猜测替代文件。已经暂停的任务仍需明确重试；旧服务需重启后才会使用这项恢复逻辑。

关闭自动处理：`node integrations/local-mcp/connect.mjs --runner manual`。停止整个服务：`node integrations/local-mcp/connect.mjs --stop`。扩展中关闭 MCP 不会停止已经交给本机服务的任务。

## 数据管理与排错

- `connection.json` 保存配对密钥，`board.json` 保存看板、留言和去重记录。不要将数据目录放在源码仓库里或提交这些文件。操作系统用户目录权限保护本机文件，Ampira 不额外加密。
- 服务启动日志和 MCP 工具不输出密钥。密钥只供扩展与本机接口配对；已授权 AI 客户端通过 stdio 读取内容，其模型数据处理政策另行适用。
- 提示 `EADDRINUSE`：关闭占用端口的旧实例，或改用其他端口。提示 `data-directory-in-use`：确认只有一个客户端启动该目录；如果进程曾被强制结束，确认它已停止后再删除该目录中的 `server.lock`，不要删除数据文件。
- 浏览器提示无法连接：确认 AI 客户端中的 MCP 服务正在运行、地址和端口一致、配对密钥正确、可选本机权限未撤销。
- 服务记录达到容量上限时先备份数据，再选择新目录启动并重新配对；不要自行删改去重记录以免旧请求再次执行。
- 完全删除：先停止 MCP 服务，再删除自己的服务数据目录；浏览器中移除连接并按需恢复出厂设置。停止或卸载扩展不会删除辅助服务文件。

实现使用 MCP `2025-11-25` stdio 生命周期与工具接口，同时协商兼容 `2024-11-05`、`2025-03-26`、`2025-06-18`。不提供远程 HTTP MCP 端点；本机 HTTP 仅供扩展使用。

## 可选的资讯整理

在 AI 助手看板的“接管内容”中勾选“资讯整理”，扩展会提交自动、批量或单条资讯整理任务，包含同语言摘要和外文翻译。ampira_get_pending 的 kind 为 summary 时，根据 locale 和已有摘录整理 items，调用 ampira_complete_task，参数为 taskId 与 summaries（每项 id、title、summary 字符串数组）。每批最多五条，每条摘录最多 2,000 字符；返回标题最多 64 字符，摘要最多三行、合计 200 字符。仅纠正被拒绝条目一次，不自行抓取网页或补写事实。

工具清单现在包括 ampira_get_pending、ampira_complete_task、ampira_get_module、ampira_publish。已运行的后台服务需先用 connect.mjs --stop 停止，再重新加载 AI 客户端连接。共享整理缓存保存在本机，不含外部模型实际账单。

## 简报与问答的省用量流程

默认由插件处理日常数据与操作，MCP 主要接收 brief、question 和可选 summary 任务。按用户请求通过 ampira_get_pending 的 kind 限定工作类型；无任务即停止，不创建模型轮询。可附 knownRevision 避免重复读取未变化的任务。

brief 任务由插件准备最多 12 条证据（最多 4,500 字符），每天完成后复用。以 ampira_complete_task 提交 taskId、brief 和可选 sourceIds。question 任务最多 4 条，附加上下文最多 1,200 字符；以 taskId、replies 数组提交答案，每项包含原消息 id、text 和可选 sourceIds。程序补齐回复编号、时间与来源链接。不要为了填看板重复搜索、重新总结已有结果或抄写完整模块。

ampira_get_module 支持 today、replies 和任务 context，默认 10 条预览，最大 20 条、总长 6,000 字符。用 ids 选择详情、cursor 翻页；module=context 配合 taskId 读取任务资料。内容发生变化会使旧 cursor 失效，重新从第一页读取即可。truncated 或 briefTruncated 表示文字不完整，不应当作完整来源。

此次更新涉及新增简报接口与工具参数。已运行的服务需先执行 connect.mjs --stop，再重新加载 AI 客户端的 MCP 连接。Node 程序不替代 AI 客户端的计费；工具返回体积减少并不等于整段会话的 token 账单同比下降。
